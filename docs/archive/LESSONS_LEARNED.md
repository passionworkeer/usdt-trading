## 🎓 量化交易的残酷教训

### 教训 1: 数学不能猜

**错误公式**:
```python
# 我随便写的
position_size = (risk_amount * atr) / (atr * stop_distance_pct)
```

**问题**:
- `atr * stop_distance_pct` 是什么鬼？
- ATR 单位是价格（美元）
- stop_distance_pct 是百分比（无单位）
- 两者相乘 = 量纲错误！

**正确推导**:
```
已知:
- Account_Capital = $10,000
- Risk_Percentage = 2%
- ATR = $500
- 想用 2×ATR 作为止损

推导:
1. 风险金额 = $10,000 × 2% = $200
2. 止损距离 = 2 × $500 = $1,000
3. 仓位数量 = $200 / $1,000 = 0.2 BTC

验证:
- 入场：0.2 BTC @ $50,000 = $10,000
- 止损：0.2 BTC @ $49,000 = $9,800
- 损失：$200 ✅ 正好 2%
```

**教训**: 每个公式必须有严格的数学推导和量纲验证。

### 教训 2: 数据精度决定策略质量

**错误假设**:
```python
# 假设 1 小时 K 线的成交量均匀分布
price_bins = 100
volume_per_bin = total_volume / 100
```

**现实**:
```
真实 K 线内成交量分布：
50200-50250: ████████████ 500 BTC
50150-50200: ███ 50 BTC
50100-50150: ██ 20 BTC
50050-50100: █ 10 BTC

我的假设：
50000-50500: ▬▬▬▬▬▬▬▬▬▬ 均匀分布 ❌
```

**教训**:
- K 线数据丢失了太多信息
- 真正的 Volume Profile 需要 Tick 数据
- 用粗糙数据只能得到粗糙结论

### 教训 3: 静态模型在动态世界中失效

**错误实现**:
```python
# 静态 70% 阈值
if correlation > 0.7:
    return False  # 拒绝开仓
```

**真实市场**:
```
正常时间:
BTC-ETH = 0.65 → 允许同时持有 ✅

极端行情（闪崩）:
BTC-ETH = 0.98 → 仍然允许持有 ❌
→ 系统性风险爆发
→ 同时亏损
```

**修复**:
```python
# 动态检测极端行情
if avg_correlation > 0.8:
    extreme_mode = True
    # 极端模式下只允许单一仓位
```

**教训**: 金融市场的相关性是动态的，极端情况下所有资产相关性趋近 1。

### 教训 4: 回测不包含真实成本 = 自欺欺人

**错误回测**:
```python
commission = 0.001  # 0.1%
slippage = 0.0005   # 0.05%

# 回测结果：Sharpe = 2.5 ✨ 看起来很棒！
```

**实盘现实**:
```
真实成本：
- Taker Fee: 0.1%
- 市价单滑点: 0.1% - 0.5%
- 来回成本: 0.2% - 1.0%

# 实盘结果：Sharpe = 0.5 甚至亏损 💀
```

**教训**: 回测必须包含严苛的摩擦成本，否则只是"纸上富贵"。

---

### 教训 5: 前视偏差是最容易犯的错误

**错误代码**:
```python
# 用当根 K 线的收盘价触发当根交易
if df['close'][i] > df['bb_upper'][i]:
    signals[i] = 1  # 买入
```

**问题**:
- 当你知道收盘价时，这根 K 线已经走完了
- 你无法在这个价格买入
- 这是"作弊"

**正确做法**:
```python
# 用 T-1 数据触发 T 交易
if df['close'][i-1] > df['bb_upper'][i-1]:
    signals[i] = 1  # 下一根 K 线开盘买入
```

**教训**: 回测中只能用"过去"的数据决策，不能用"未来"的信息。

## 🎯 量化交易的核心原则

### 1. 数学严谨性

```
每个公式必须：
✓ 有严格的数学推导
✓ 量纲一致
✓ 极端值验证
✗ 不能凭直觉
```

### 2. 数据真实性

```
必须使用：
✓ 真实的市场数据
✓ 准确的时间戳
✓ 完整的成交记录
✗ 不能用估算代替
```

### 3. 摩擦成本

```
必须包含：
✓ 手续费 (Maker/Taker)
✓ 滑点模型
✓ 资金成本
✓ 极端情况惩罚
```

### 4. 前视偏差检测

```
必须确保：
✓ 只用 T-1 数据做 T 决策
✓ 所有用 shift(1) 验证
✗ 不能用未来信息
```

### 5. 极端场景测试

```
必须模拟：
✓ 闪崩 (Flash Crash)
✓ 涨跌停 (Limit Up/Down)
✓ 流动性枯竭
✓ 系统性风险
```
